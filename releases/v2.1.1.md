# v2.1.1 — `run_command` runs through your login shell, with your environment

- **User shell, not `sh`** — commands execute via the resolved login shell (`FS_MCP_SHELL` > `$SHELL` > `/etc/passwd` > `sh`) instead of a hardcoded `sh -c`, foreground and background alike.
- **The environment an interactive login session actually has** — captured once via marker-delimited `env -0` and cached, so version-manager shims (nvm, pyenv, cargo) resolve. A supervisor-launched server used to hand children a bare PATH, leaving `npx` and `node` simply missing for agents while they worked fine in the user's terminal.
- **Auto-refresh, no restart** — each call stats the shell's rc files (microseconds) and re-captures before running when one changed; a 15-minute TTL covers files sourced indirectly, like `nvm.sh`.
- **bash sources `~/.bashrc` explicitly** — login bash reads only the profile chain, yet version managers install their loader in `.bashrc`; hosts whose `~/.profile` doesn't chain it were missing all of it.
- **Degrades, never fails** — a capture timeout (5s) or unparseable result falls back to the server's own environment and retries on a shorter interval.
- **`cwd` is declared in output schemas** — every structured result carries an injected `cwd` key, but `tools/list` never advertised it, so schema-validating clients saw an undeclared extra property on every call.
- **`--doctor` reports the shell** — resolved shell, whether the env capture succeeded, and how many variables it carries.
- **Config:** `FS_MCP_SHELL` overrides shell resolution. Nothing to do on upgrade.
